## Implemented pure domain

- Versioned state starts at the Chapter 1 card. One forward action per Chapter 1 step plus an authorized previous-dialogue action where available; the Chapter 2 handoff offers only PREVIOUS, composite action ID, monotonic revision; arbitrary targets and stale revisions are rejected. A separate review cursor is bounded within reached Chapter 1 presentation from L02 through the Chapter 2 handoff, including narration, information and already-applied events. Review never replays events; the initial card and dark beats cannot be reached by new PREVIOUS commands. Review does not rewind authoritative progress, repeat events, regenerate INTRO-RANDOM or debit energy.

## Integrated local session and transport

- Additive Prisma migration `20261116173000_chapter_one_sessions` adds a unique SHA-256 token digest, narrative version, JSON state, monotonic revision, expiry and command receipts. Existing foundation rows are preserved. The 30-day expiry is provisional for local validation; cleanup and production policy remain AMI-010.
- The server issues 32 random bytes encoded as a cookie capability; the same-origin facade forwards only that cookie, marks it HttpOnly/SameSite=Lax and Secure on HTTPS. New game is explicit; continuing restores the existing run. A confirmation protects replacement of the browser's current resume target; the prior row is not deleted. No account or client-supplied state.
- Mutations lock the session row in a PostgreSQL transaction, compare revisions and store unique command receipts atomically. Duplicate identical commands replay the current authorized view; conflicting IDs or stale revisions return 409. A distinct read-only history cursor persists without rewinding events. No provider calls inside transactions.
- Next.js allowlists the five game endpoints, checks mutation Origin, validates the asset key, proxies only the session cookie and uses private/no-store responses. Both API and facade require AMI_DEV_PREVIEW=1 for local integration. Production origin, rate limiting, retention and comprehensive security review remain pending.
- Local root reuses the approved wordmark, palette, typography, layout and cues. CENA-01 is a stable image source across L02/L03; only the authorized current asset is requested. Wake optics wait for image load, are removed at L03, and honor reduced motion. Diagnostics appear only after E-JOIN on illustrated beats, in a compact strip within the existing title/Menu header row; localized personal memory label and lock icon do not change the underlying restriction. Arrow captions and native arrow tooltips are omitted; server actions remain unchanged. Long dialogue is subdivided into authored beats; measured local pagination remains an accessibility fallback without visible page numbers, and advancing local pages does not mutate the server. The owner accepted the refined layout and header after local playtest; independent browser automation and full responsive/accessibility audit remain later work.
- `/preview` retains the isolated approved visual fixture. The merged Chapter 1 baseline ended at the Chapter 2 card. PR #22 candidate extends the campaign to the Chapter 3 card with a development notice; no fake later encounter or generated story.
